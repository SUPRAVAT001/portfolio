Framework & Application Architecture

The system is engineered as a clean, modular Python application with strict separation of concerns across data persistence, business logic, templates, and security middleware:

  • Version Boundaries: The application itself is versioned as TodoApp v1.0.0, powered by the FastAPI framework (v0.139.2 / v0.141.x) running on Uvicorn v0.52.1.
  • Relational Data Layer: Backed by SQLAlchemy 2.0 with fully typed declarative models (Users and Todos). Foreign key constraints enforce strict referential integrity with ON DELETE CASCADE so deleting a user cleanly purges their associated todos.
  • Database Migrations: Managed via Alembic. The current head migration is 0002_reconcile_schema, which tightens NOT NULL constraints, establishes server defaults (is_active=true, role='user', complete=false), and creates a performance index on owner_id.
  • Multi-Tenant Data Isolation: Every Todo query and mutation is strictly scoped at the database layer with Todos.owner_id == current_user.id, guaranteeing that no user can access or tamper with another tenant's tasks.

Authentication & Security Engineering

Security was engineered from first principles rather than relying on default framework assumptions:

  • Dual-Channel Authentication: Serves browser users via HTTP-only, SameSite="lax", Secure JWT session cookies, while simultaneously exposing a JSON REST API authenticated via standard Authorization: Bearer <token> headers via POST /auth/token/login.
  • HMAC-SHA256 CSRF Middleware: Custom HTTP middleware ensures every browser session holds a cryptographically signed CSRF cookie. State-changing POST requests require a matching hidden form input token, preventing cross-site request forgery.
  • Password Security: User passwords are encrypted using bcrypt via passlib with individual salts; zero plaintext passwords are ever persisted or logged.
  • Role-Based Access Control (RBAC): Public user registration strictly assigns role="user". Administrative endpoints (system statistics, user activation/deactivation) require role="admin". Deactivated users (is_active=False) are immediately blocked from logging in.

Production OCI Deployment & Systemd

Deployed on an Oracle Cloud Infrastructure (OCI) Compute Instance (VM.Standard.E2.1.Micro, 1GB RAM) in the ap-mumbai-1 region. Because micro-instances have strict memory limits, running heavy container orchestration engines risks Out-Of-Memory (OOM) failures. The application was engineered to run directly as a native Linux service:

# /etc/systemd/system/todoapp.service
[Unit]
Description=FastAPI Todo Application
After=network.target

[Service]
User=opc
WorkingDirectory=/home/opc/apps/todoapp/FASTAPI_PRAC
EnvironmentFile=/home/opc/apps/todoapp/FASTAPI_PRAC/.env
ExecStart=/home/opc/apps/todoapp/FASTAPI_PRAC/.venv/bin/uvicorn TodoApp.main:app --host 127.0.0.1 --port 8000 --workers 1
Restart=always
RestartSec=5s

[Install]
WantedBy=multi-user.target

Fronted by a Caddy v2 reverse proxy that automatically obtains and renews Let's Encrypt TLSv1.3 certificates via elliptic curve cryptography (prime256v1). Caddy handles HTTP/2 and HTTP/3 QUIC negotiation, gzip/zstd compression, and enforces security headers (HSTS, X-Content-Type-Options: nosniff, X-Frame-Options: DENY).
